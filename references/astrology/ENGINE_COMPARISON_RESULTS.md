# Astrology Engine Comparison Results｜占星計算引擎初步比對結果

Status: **REFERENCE-ONLY / RESEARCH RESULT｜僅供參考／研究結果**

Playbook baseline at branch start: `masini1491/ai-divination-playbook@18d75bd0e7466b120094be6f681af04f2445d209`

This result belongs to the Cold Astrology research line. It does **not** establish a production engine authority, production tolerance, or routing admission.

## 1. Research question

The first executable comparison asks a narrow question:

> Under the same fixed-offset civil time, coordinates, tropical zodiac, geocentric center, and Placidus houses, how closely does a `pyswisseph` runtime agree with reviewed `tri-horoscope` fixtures generated by the Astronomy Engine family?

This is a **cross-implementation agreement probe**, not an accuracy proof.

## 2. Reviewed external evidence

Astronomy-family comparison targets come from:

- `kounkt/tri-horoscope@11318426c52c222eea108583ca45420c864825ca`
- implementation: `src/natal_v0.py`
- reviewed fixtures:
  - `tests/E1_south_sydney.json`
  - `tests/E4_time_unknown.json`
  - `tests/E5_highlat_helsinki.json`

The reviewed implementation identifies Astronomy Engine as its planetary calculation engine. Its README says the shipped golden fixtures are self-generated from fictional birth data and that development was cross-checked against an independent third-party implementation.

Important boundary:

```text
tri-horoscope fixture
!= independent astronomical ground truth
```

The fixture is useful as a pinned Astronomy-Engine-family output for cross-implementation comparison.

## 3. Comparison runtime

Local research runtime:

```text
pyswisseph version: 2.10.03
requested ephemeris flag: FLG_SWIEPH
effective returned backend: FLG_MOSEPH
zodiac: tropical
center: geocentric
house system: Placidus
bodies compared: Sun..Pluto (10)
```

### Critical backend limitation

The runtime did not have the Swiss `.se1` planetary files needed for normal SWIEPH file-backed calculation.

Although the probe requested:

```text
FLG_SWIEPH
```

the returned calculation flags reported:

```text
FLG_MOSEPH
```

Therefore this result must be described as:

> **Swiss Ephemeris API / Moshier fallback vs Astronomy Engine family**

and **not** as:

> Swiss `.se1` / DE441 vs Astronomy Engine / DE441.

The companion probe explicitly records the effective backend so this fallback cannot be hidden.

## 4. Probe

Companion executable:

[`engine_comparison_probe.py`](engine_comparison_probe.py)

It consumes a local `tri-horoscope`-style fixture JSON and compares:

- Sun through Pluto tropical geocentric longitude;
- sign agreement;
- Ascendant;
- Midheaven;
- 12 Placidus cusps;
- derived house placement.

It intentionally excludes `NorthNode` from this first result because node definition/provenance is not yet normalized between implementations.

## 5. Results

Angular differences are absolute circular differences.

| Fixture | Planet longitude max | Planet longitude mean | Sign disagreements | Asc diff | MC diff | Cusp max | Cusp mean | House mismatches |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `E1_south_sydney` | 4.682″ | 1.195″ | 0/10 | 5.243″ | 1.055″ | 5.243″ | 2.187″ | 0/10 |
| `E4_time_unknown` | 8.783″ | 3.117″ | 0/10 | 0.486″ | 1.394″ | 1.437″ | 0.811″ | 0/10 |
| `E5_highlat_helsinki` | 14.178″ | 3.446″ | 0/10 | 3.455″ | 1.279″ | 6.954″ | 3.152″ | 0/10 |

Across these three fixtures:

```text
30 planetary sign comparisons
→ 0 disagreements

30 planetary house-placement comparisons
→ 0 disagreements

maximum planetary longitude difference
→ 14.178 arcsec = 0.00394°

maximum Placidus cusp difference
→ 6.954 arcsec = 0.00193°
```

The largest planetary difference in the three-case sample occurred for Neptune in the high-latitude Helsinki fixture.

## 6. What this supports

This bounded result supports only the following research statements:

1. For these three reviewed fixtures and this configuration, Moshier-backed `pyswisseph` and the pinned Astronomy-Engine-family fixture outputs agree at arcsecond-to-low-tens-of-arcseconds scale.
2. No sign placement changed in the 30 compared planet placements.
3. No house placement changed in the 30 compared planet placements.
4. Swiss Placidus angles/cusps and the reviewed independent implementation were very close in these cases, including the Helsinki high-latitude stress fixture.
5. Runtime backend identity must be retained as provenance because requesting SWIEPH does not guarantee SWIEPH is the effective calculation backend.

## 7. What this does not support

This result does **not** establish:

- a production acceptance tolerance;
- that either implementation is astronomically correct;
- that all dates / coordinates / high latitudes behave similarly;
- `.se1`-backed Swiss Ephemeris agreement;
- JPL-file-backed Swiss Ephemeris agreement;
- node agreement;
- asteroid / fixed-star agreement;
- topocentric agreement;
- sidereal / ayanamsa agreement;
- exact transit-event-time agreement;
- applying/separating agreement;
- station-time agreement;
- timezone / DST correctness;
- house correctness near polar failure regions.

The maximum observed error must not be converted directly into a production threshold.
