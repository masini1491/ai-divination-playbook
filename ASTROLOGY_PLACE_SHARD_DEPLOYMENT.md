# Astrology place shard production deployment contract

Status: **CANONICAL DEPLOYMENT CONTRACT / PRODUCTION DATA REF NOT YET PUBLISHED**

This contract owns persistence and identity for the query-bounded Astrology place shard corpus. It does not change resolver semantics or astronomical authority.

## Selected topology

The default production transport candidate is profile `500`, matching `ASTROLOGY_PLACE_RESOLVER_ADMISSION_V1.json` default resolver semantics.

The generated corpus MUST NOT be copied into the ordinary `main` hot tree merely to make it retrievable. It is published to a dedicated generated-data ref:

```text
refs/heads/data/astrology-place-v1
```

The data ref contains the versioned `data/astrology/place/v1/profiles/500/**` shard tree plus a generated identity manifest. Ordinary ChatGPT retrieval resolves the main revision first, reads the production manifest, then retrieves only query-derived shard paths from the exact admitted data-ref commit recorded by that manifest.

## Identity coupling

Production admission requires the main manifest to pin all of:

- data ref name;
- exact data-ref commit SHA;
- generator id and generator source commit;
- source dataset SHA-256 and byte size;
- profile;
- aggregate generated digest;
- generated file count and byte count.

A moving branch name alone is never sufficient runtime identity. If the recorded data commit or aggregate identity is unavailable, retrieval fails closed.

## Publisher

Publication is a deliberate maintenance action, not an ordinary CI side effect. The publisher workflow is manual-only and must:

1. check out the exact requested main/source revision;
2. install exact `geonamescache==3.0.2`;
3. run the project-owned deterministic generator for profile 500;
4. verify the admitted source identity;
5. verify the expected aggregate digest / file count / byte count before publication;
6. create/update the dedicated data ref without force;
7. write a generated identity manifest into that same data commit;
8. report the exact data commit for a separate main-manifest admission change.

The publisher must not mutate `main`. Publication and production admission remain two separate reviewed steps.
